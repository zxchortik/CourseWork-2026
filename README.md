**1. Призначення програми**
Програма являє собою консольний застосунок (CLI) розроблений мовою C# на платформі .NET 10. Головне призначення - надання користувачу інструментарію для створення, зберігання наборів тестових запитань, проходження тренувальних сесій з урахуванням часу та аналізу результатів навчання.

**2. Короткий опис предметної області**
Предметна область охоплює сферу електронного тестування.

Тема (Topic) - логічний розділ, що об'єднує набір тестів.
Тест (Test) - набір запитань для перевірки знань.
Запитання (Question) - базова одиниця тестування, яка має текст, кількість балів за правильний вибір та тип. Реалізовано три типи запитань:
1. З однією правильною відповіддю (SingleChoiceQuestion).
2. З кількома правильними відповідями (MultipleChoiceQuestion).
3. Відкрита відповідь (OpenAnswerQuestion).

Тренувальна сесія (TestSession) - процес проходження тесту користувачем.
Результат (TestResult) - збережена інформація про успішність (бали, відсотки, допущені помилки).

**3. Основні можливості системи**
Керування контентом: Створення, редагування та видалення тем, тестів і запитань різного типу.
Налаштування програми: Зміна тривалості сесії, прохідного балу, увімкнення/вимкнення перемішування запитань та миттєвого показу правильних відповідей.
Проходження тестів: Запуск тесту з вибором кількості питань, контроль часу виконання (таймер сесії).
Перемішування питань та варіантів відповідей: Випадковий порядок питань та варіантів відповідей (із збереженням цілісності правильної відповіді).
Аналітика та історія: Перегляд минулих результатів, відображення загальної статистики успішності та визначення "найскладніших запитань" (тих, де користувач найчастіше робив помилки).

**4. Інструкція зі збирання та запуску**
Для роботи програми потрібен встановлений .NET 10.0 SDK.

1. Склонуйте репозиторій
2. Відкрийте термінал у кореневій папці проєкту.
3. Для збирання проєкту виконайте команду: dotnet build
4. Для запуску застосунку виконайте команду: dotnet run --project TestSimulator.UI
5. Для запуску Unit-тестів виконайте: dotnet test

**5. Інструкція з використання**
Взаємодія з програмою відбувається через консольний інтерфейс шляхом введення команд.
Після запуску ви побачите запрошення до вводу >.

Базовий алгоритм роботи:
1. Введіть create-topic, щоб створити нову тему.
2. Введіть create-test <ID_теми>, щоб додати до неї тест.
3. Введіть create-question <ID_тесту> та слідуйте інструкціям на екрані для додавання питань.
4. Введіть list для перегляду всіх тем та їхніх ID.
5. Введіть start <ID_тесту>, щоб розпочати проходження.

Основні команди:
* help - показати довідку з переліком усіх команд.
* settings - відкрити інтерактивне меню налаштувань програми.
* history - показати історію всіх пройдених тестів.
* stats - показати детальну аналітику (середній бал, топ помилок).
* exit - завершити роботу програми.

**6. Формат і спосіб збереження даних**
Дані зберігаються локально у вигляді текстових файлів у форматі JSON.
За це відповідає компонент JsonTestRepository.

Для забезпечення збереження різних типів запитань (SingleChoice, MultipleChoice, OpenAnswer) в одному списку використовується поліморфна серіалізація/десеріалізація за допомогою атрибутів [JsonDerivedType]. Файли автоматично створюються та оновлюються у директорії Data/ відносно виконуваного файлу.

**7. Підготовлені файли з прикладами даних**
Проєкт включає папку Data/ із попередньо заповненими даними для демонстрації функціональності без необхідності ручного введення з нуля:
1. topics.json - містить ієрархію тем, тестів та приклади запитань усіх трьох підтримуваних типів. Демонструє поліморфну структуру збереження даних.
2. config.json - містить попередньо налаштовані конфігурації (наприклад, увімкнене перемішування, тривалість сесії 30 хв).

**8. Основні модулі, компоненти та їхня відповідальність**
Проєкт побудований за принципами N-Tier (багатошарової) архітектури, що забезпечує низьку зв'язність і легке тестування:

1. TestSimulator.Domain (Моделі та Сутності)
Містить класи предметної області (Topic, Test, Question, TestSession, TestResult).
Містить перелік конфігурацій (AppConfig), Enum та користувацькі класи винятків (TestSimulatorException).
Відповідає виключно за структуру даних і базову бізнес-логіку об'єктів (наприклад, поліморфний метод перевірки відповідей CheckAnswer).

2. TestSimulator.DAL (Data Access Layer - Робота з даними)
ITestRepository - інтерфейс, що гарантує принцип Dependency Inversion.
JsonTestRepository - імплементація інтерфейсу для роботи з файловою системою (читання/запис JSON-файлів).

3. TestSimulator.BLL (Business Logic Layer - Бізнес-логіка)
TestService - сервісний клас, що обробляє логіку програми. Відповідає за валідацію, старт сесії, підрахунок балів, логіку перемішування колекцій.

4. TestSimulator.UI (User Interface - Інтерфейс користувача)
Program - точка входу, ініціалізація залежностей та маршрутизатор команд.
TestEditorView - відповідає за взаємодію з користувачем під час створення/редагування контенту.
TestSessionView - консольний інтерфейс проходження тесту (вивід меню, збір відповідей).

5. TestSimulator.Tests (Модульне тестування)
Проєкт із тестами, що використовує NUnit як тестовий фреймворк. Він охоплює як класичні Unit-тести (для перевірки бізнес-логіки та алгоритмів), так і інтеграційні сценарії (для перевірки взаємодії компонентів системи між собою).

**9. Конфігурація проєкту**
Загальні налаштування застосунку (AppConfig) зберігаються у файлі config.json і можуть бути змінені користувачем прямо в програмі за допомогою команди settings.
Доступні параметри:
* SessionDurationMinutes - час (у хвилинах), виділений на проходження одного тесту (за замовчуванням: 30).
* PassingScorePercentage - відсоток правильних відповідей, необхідний для успішного складання (за замовчуванням: 60%).
* ShuffleQuestions - чи потрібно випадково перемішувати питання та варіанти відповідей перед початком сесії (за замовчуванням: true).
* ShowCorrectAnswersImmediately - режим "навчання", за якого програма миттєво повідомляє, чи відповів користувач правильно на поточне питання (за замовчуванням: false).
